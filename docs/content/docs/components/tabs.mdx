标签页家族。行为全部由 React Aria 承担：TabList 内是一个 roving focus
（整组只占一个 Tab 停留点），方向键在标签间移动并随 `orientation` 换轴，
`Tab` 与 `TabPanel` 的 `aria-controls` / `aria-labelledby` 互指由 RAC 按 `id` 自动接线。
组合就是全部 API —— 根组件 `Tabs` 上没有 `items`，也没有配置对象。
（标签集合由数据算出来时，用 RAC 的动态集合写法：
`<TabList items={tabs}>{item => <Tab id={item.id}>{item.title}</Tab>}</TabList>`。）

公开名严格对齐 React Aria：**`Tabs` / `TabList` / `Tab` / `TabPanel`**。
shadcn 源码里那套 `TabsList` / `TabsTrigger` / `TabsContent` 是 Radix 留下的别名 ——
底下明明是 React Aria 组件，名字却是另一个库的。接缝层刻意把它改回来，
这样 props（`selectedKey` / `onSelectionChange` / `keyboardActivation` / `disabledKeys`）
和组件名说的是同一门方言，查文档时直接对得上 React Aria。

结构永远是：`Tabs` 里放一个 `TabList`（内含若干 `Tab`），后面跟若干 `TabPanel`。

## 基础用法

`Tab` 的 `id` 就是它的 key，同名 `id` 的 `TabPanel` 自动配对；
`defaultSelectedKey` 指定初始选中（不给则选第一个**未禁用**的标签）。
`TabList` 的 `aria-label` 必给 —— 它是这组标签页的无障碍名。
`TabIndicator` 是那块会滑动的选中标记，见[下一节](#滑动指示器)：

## 滑动指示器

`TabIndicator` 把选中标记从「每个标签各画各的」换成**一个会滑动的元素**：
切换标签时它补间过去（200ms ease-out），而不是 A 灭 B 亮。

它跟随的顺序是 **悬停 → 聚焦 → 选中**：鼠标移到别的标签上它就滑过去，
移开再滑回真正选中的那个，所以它表达的是「你即将选中的那个」。
中间那档「聚焦」是给 `keyboardActivation="manual"` 用的 ——
那时方向键只移焦点不改选中，指示器跟着焦点走才看得出来将要选中谁。

写在 `TabList` 里即可，位置随意；放进去之后标签自身就不再画选中底色，
两个 `variant` 都支持（`default` 是滑动的胶囊，`line` 是滑动的下划线）：

```tsx
<TabList aria-label="项目仪表盘">
  <TabIndicator />
  <Tab id="overview">概览</Tab>
  <Tab id="analytics">分析</Tab>
</TabList>
```

`prefers-reduced-motion` 下自动降级为瞬时移动；首次渲染直接就位，不做滑入动画。
标签宽度变化（字体加载完、角标数字变了）会自动重新测量。

不写 `TabIndicator` 也完全可用 —— 那就是每个标签各画各的选中态，没有过渡。

换轴是 RAC 读 `orientation` 自己做的，不用另外配。指示器同样换轴：

`selectedKey` + `onSelectionChange` 把选中态交给外部 state，
组件只负责渲染 —— 从 Tabs 之外切换标签页（下面的「下一个」按钮）就靠这个：

## 禁用

两种写法等价：`<Tab isDisabled>` 就近声明，或根上的 `disabledKeys` 传一组 key ——
后者适合禁用集合由数据算出来的场景。禁用的标签会被键盘导航跳过。

## 键盘激活方式

默认 `keyboardActivation="automatic"`：焦点走到哪，面板就切到哪。
面板加载昂贵（发请求、渲染大图表）时，键盘路过就会白白触发一次 ——

## 状态 hook

`useTabsState()` 读取 React Aria 的 `TabListState` —— 这是 RAC 自己的 state 层
（经 `TabListStateContext`），不是我们另建的一套。自定义部件直接取用，
不必把选中态当 props 一层层穿下来：

```tsx
import type { ReactElement } from 'react'
import { Tab, TabList, TabPanel, Tabs, useTabsState } from '@gedatou/cadenza-ui'

// 自定义部件:显示「第几项 / 共几项」。写成 Tabs 的直接子节点,
// 并在拿到 null 时返回 null —— 原因见下方两条规则
function TabPosition(): ReactElement | null {
  const state = useTabsState()
  if (state === null)
    return null

  const { selectedKey, collection } = state
  const index = [...collection].findIndex(node => node.key === selectedKey)

  return (
    <span className="text-xs text-muted-foreground">
      {`第 ${index + 1} 项 / 共 ${collection.size} 项`}
    </span>
  )
}

export default function TabsPositionDemo(): ReactElement {
  return (
    <Tabs defaultSelectedKey="overview">
      <TabList aria-label="项目仪表盘">
        <Tab id="overview">概览</Tab>
        <Tab id="analytics">分析</Tab>
      </TabList>
      <TabPosition />
      <TabPanel id="overview">…</TabPanel>
      <TabPanel id="analytics">…</TabPanel>
    </Tabs>
  )
}
```

| 字段 | 说明 |
| --- | --- |
| `selectedKey` | 当前选中的 key（即那个 `Tab` 的 `id`） |
| `setSelectedKey(key)` | 切换选中；非受控时直接改，受控时会走你的 `onSelectionChange` |
| `collection` | 标签集合，可迭代拿到每个 `Tab` 节点（`key` / `textValue` …），`size` 是总数 |
| `isDisabled` | 整组是否禁用 |

返回值是 `TabListState | null`，两种情况下为 `null`，都得处理：

- **RAC 的集合收集遍。** `Tabs` 会把 children 先在一个隐藏的 `<template>` 里
  渲染一遍，用来构建标签集合；那一遍还没有 state。返回 `null` 即可，
  RAC 自己的组件也是这么判断的。
- **在 `TabPanel` 内部。** RAC 在面板里**故意**把 tabs 的 context 重置为 `null`，
  这样面板里再嵌一组 `Tabs` 不会串到外层的状态上。要在面板里拿状态，
  用 `TabPanel` 的 render props：`<TabPanel id="a">{({ state }) => …}</TabPanel>`。

`TabList` 里也放不了自定义部件 —— 它只渲染标签集合本身，别的子节点会被丢弃
（这正是 `TabIndicator` 要由 `TabList` 提到集合之外去渲染的原因）。

## 键盘交互

| 按键 | 行为 |
| --- | --- |
| `→` / `←` | 横向（默认）时切换到相邻标签，到头循环 |
| `↓` / `↑` | `orientation="vertical"` 时切换到相邻标签 |
| `Home` / `End` | 跳到第一个 / 最后一个标签 |
| `Tab` | 进入时落在选中的标签上（整组只占一个停留点），再按一次离开 TabList 进入面板 |
| `Enter` / `Space` | 仅 `keyboardActivation="manual"`：确认当前焦点所在的标签 |

禁用的标签在以上所有导航中都会被跳过。

## Props

属性顺序统一是：**必填 → 非受控默认值 → 受控值 → 回调 → 行为开关 → 外观 → `className`**。

每个部件的 Props 表后面跟一张**状态**表。左列是 React Aria 挂在 DOM 上的
`data-*`，Tailwind 直接当变体写（`data-selected:bg-background`）；右列是同一个
状态在 render props 里的名字，写 `{({ isSelected }) => …}` 时取用 —— 同一组状态的
两个出口，按手头顺手的用。表里没有的 `data-rac` / `data-collection` / `data-key`
是 RAC 的内部标记，不要依赖。

### Tabs

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `defaultSelectedKey` | `Key` | 第一个未禁用的标签 | 非受控初始选中 |
| `selectedKey` | `Key` | — | 受控选中的标签 id；RAC 的标签页始终有一个选中项，不接受 `null` |
| `onSelectionChange` | `(key: Key) => void` | — | 选中变化回调 |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | 排列方向，同时决定方向键的轴 |
| `keyboardActivation` | `'automatic' \| 'manual'` | `'automatic'` | 方向键是否顺带切换面板 |
| `disabledKeys` | `Iterable<Key>` | — | 按 key 批量禁用标签 |
| `isDisabled` | `boolean` | `false` | 整组禁用 |
| `className` | `string` | — | 根元素类名 |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-orientation` | 始终有值：`horizontal` / `vertical` | `orientation` |

### TabList

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `aria-label` | `string` | — | 这组标签页的无障碍名，**必给** |
| `items` | `Iterable<T>` | — | 动态集合数据源，配函数 children 使用 |
| `variant` | `'default' \| 'line'` | `'default'` | 胶囊底色 / 底部指示线 |
| `className` | `string` | — | 类名 |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-orientation` | 始终有值，跟随根组件 | `orientation` |
| `data-variant` | 始终有值：`default` / `line`（我们加的，不是 RAC 的） | — |

`TabList` 的 render props 里还有 `state`，就是 [`useTabsState()`](#状态-hook) 拿到的那个
`TabListState`。

### TabIndicator

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `className` | `string` | — | 类名（改颜色、圆角、过渡时长都从这里来） |

写在 `TabList` 的子节点里；它本身不渲染，由 `TabList` 提到标签集合之外去渲染
（RAC 的 `TabList` 只渲染集合，别的子节点会被丢弃）。它自己没有状态 ——
跟随哪个标签是内部算出来的，外部读不到，也不该读。

### Tab

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `id` | `Key` | — | 这个标签的 key，与对应 `TabPanel` 的 `id` 相同 |
| `isDisabled` | `boolean` | `false` | 禁用这一个标签 |
| `href` | `string` | — | 链接型标签，渲染成 `<a>`（路由驱动的标签页用它） |
| `className` | `string` | — | 类名 |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-selected` | 是当前选中的标签 | `isSelected` |
| `data-hovered` | 指针悬停其上；触摸不触发，键盘也不触发 | `isHovered` |
| `data-pressed` | 指针按住未松开，或空格/回车按住 | `isPressed` |
| `data-focused` | 拿到焦点，不分来源 | `isFocused` |
| `data-focus-visible` | 拿到焦点**且**应当显示焦点环（键盘来的） | `isFocusVisible` |
| `data-disabled` | 被自身 `isDisabled` 或根上的 `disabledKeys` 禁用 | `isDisabled` |

`data-focused` 和 `data-focus-visible` 的区别就是焦点环该不该出现：鼠标点上去两者
只有前者，键盘走过去两者都有。样式挂 `data-focus-visible` 才不会在点击时闪一下框。

### TabPanel

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `id` | `Key` | — | 与对应 `Tab` 的 `id` 相同即自动配对 |
| `shouldForceMount` | `boolean` | `false` | 未选中时也保留在 DOM（默认只渲染选中的那个） |
| `className` | `string` | — | 类名 |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-focused` | 面板拿到焦点（它自身可聚焦，Tab 键从标签走进来） | `isFocused` |
| `data-focus-visible` | 焦点且应当显示焦点环 | `isFocusVisible` |
| `data-inert` | `shouldForceMount` 保留下来、但当前未选中的面板 | `isInert` |
| `data-entering` / `data-exiting` | 面板带进出场动画时，动画运行期间 | `isEntering` / `isExiting` |

面板的 render props 里同样带 `state`。这是在面板内部读标签页状态的**唯一**入口 ——
`useTabsState()` 在这里返回 `null`，原因见[上一节](#状态-hook)。

`TabsProps` / `TabListProps` / `TabProps` / `TabPanelProps` / `TabIndicatorProps`
五个类型也一并导出，业务层再包一层时直接复用；`TabsContext` 也导出 ——
需要从上层给整个子树设默认值（`orientation`、`keyboardActivation`）时用它。
