可搜索、游标分页无限滚动的选择器家族。行为全部由 React Aria 承担：`Autocomplete`
用虚拟焦点把搜索框和列表接起来（输入框保持 DOM 焦点，方向键在列表里移动），
`ListBox` 提供选择语义、方向键 / Home / End / typeahead。大数据集可用
`virtualized` 开启 TanStack Virtual 行虚拟化，见下文。

分层也照 React Aria 的方式：底下是 **hooks 层**（状态与行为），中间是
**组合式 parts**（context 接线、按书写顺序渲染），`InfiniteCombobox`
是把这些一把组好的**便利层**。日常用便利层就够；要改结构时降到 parts
层自由组合，见「[组合式架构与 hooks](#组合式架构与-hooks)」。

每个 demo 下方都附完整源码（View Code 展开、右上角复制）；异步接口用 Promise
模拟（300–500ms 随机延时），mock 数据源在 `demos/lib` 里。

## 单选

打开后滚到底会自动加载下一页；输入会防抖 300ms 后落到 `queryValue`，由数据层重新请求。

<ComponentPreview name="infinite-select/single" />

触发器是 `children`，必须是 React Aria 意义上可按压的元素（库里的 `Button` 即可）——
弹层开合、焦点归还、Esc 关闭都由 `DialogTrigger` 接管。传函数可以拿到当前状态做摘要展示。

## 多选 + 暂存提交

`commitOnClose` 下，弹层内的勾选只是草稿，**关闭弹层才提交一次** `onChange` ——
适合筛选场景（每勾一下就请求一次太吵）。footer 里的清空 / 确定通过 context 拿到
`clear` / `close`，不需要你穿线。

<ComponentPreview name="infinite-select/multiple" />

多选的 `onChange(items, ids)` 里 **`ids` 是权威全集**：预选 id 落在未加载的页上时，
它有 id 没对象，`items` 只回显已加载的那些。持久化请存 `ids`。

## 虚拟化

默认情况下，加载了多少行就渲染多少行。开启 `virtualized` 后行渲染交给
TanStack Virtual：**任何时刻只有视口内可见的行、加上视口外少量预渲染的行
（overscan）存在于 DOM**——加载一万行，DOM 里也始终只有几十个节点。
下面的 demo 一次拉满 10000 条（无翻页）：

<ComponentPreview name="infinite-select/virtualized" />

```tsx
<InfiniteCombobox<Person> virtualized rowHeight={32} … />
```

开启前要知道的三个取舍：

1. **行高固定**为 `rowHeight`（默认 32px）——虚拟化靠固定行高换取零测量、零跳动；
   自定义 `renderItem` 比默认行高时必须同步调大它。
2. **键盘和读屏的作用域变窄**：React Aria 只认识 DOM 里的那几十行，所以打字定位
   （typeahead）、Home / End 只在这几十行内生效，读屏播报的列表总数也是这个数。
3. 因此**几百行以内不建议开**——不开时 React Aria 认识完整列表，上面这些能力
   都是全量的，而几百行的 DOM 根本不构成性能问题。

加载下一页的触发时机与非虚拟模式一致（提前约 1 个视口预取，由
`loadMoreScrollOffset` 控制），无需关心。

放在 slots 末尾自然落在面板底部：

### 加载中:统一的磨砂覆盖层

加载**没有文案插槽**——无论首屏还是刷新，视觉统一是列表区内建的
[LoadingOverlay](/docs/components/loading-overlay)，一种加载长相。**只盖列表区**：
搜索框在覆盖范围之外，打字正是触发刷新的动作，盖住输入框等于打断输入。

**首屏**（`isLoading` 且还没有结果）：列表壳给最低高度（`min-block-24`）防坍缩，磨砂盖在空白上：

<ComponentPreview name="infinite-select/loading" />

**刷新**（`isLoading` 且上一批结果还在——业务层配 react-query 的 `placeholderData`）：
列表原地保留、被磨砂盖住。

#### InfiniteSelectLoadingOverlay:定制磨砂

在组合通道里放它即可定制上面那层磨砂。它是 TabIndicator 式的**标记部件**——
写在哪里都不渲染（绝对定位的覆盖层没法住在面板的文档流里），由 List 部件
提升到列表壳的位置渲染；`children` 替换居中的 Spinner，`className` 调磨砂浓度，
`isLoading` 是基座的接线、不在它的 props 里。直接子级或 Fragment 内有效，
包进自定义组件会找不到（与 TabIndicator 同一限制）。用 `InfiniteCombobox` 时
放进 `slots` 即可：

（旧版的 `InfiniteSelectLoading` 文案插槽已移除，定制走 `InfiniteSelectLoadingOverlay`。）

### InfiniteSelectStatus:状态容器

三个状态插槽最终都渲染成同一个 `role="status"` 容器（状态切换会被读屏播报），
它也单独导出，自定义状态视觉时可复用。

加载更多的指示不走插槽——它必须渲染在**列表滚动流的末尾**（位置由基座决定），
用 `loadingMoreIndicator` prop 传：预取提前触发，停在顶部的用户根本看不到它，
只有滚到底部、恰好在等下一页的人才会看见。

## 动作上下文

footer 部件之所以不需要穿线，是因为面板内有一个**动作上下文**。
`useInfiniteSelectActions<T>()` 在 slots 里的任何部件中都可调用，返回
`InfiniteSelectActions<T>`：

| 字段 | 说明 |
| --- | --- |
| `selectedIds` | 当前选择的权威全集（含未加载页的 id） |
| `selectedItems` | 已加载页的选中对象（口径与 `onChange` 的 `items` 一致） |
| `clear()` | 清空选择 |
| `close()` | 关闭弹层（`commitOnClose` 下即提交草稿） |

`InfiniteSelectClearButton` / `InfiniteSelectConfirmButton` 内部就是调它；
「插槽」一节 Footer demo 里的「已选 N」自定义部件也是。两个注意点：

- 在 provider 之外调用会**直接抛错**（fail loud），所以它只能出现在 slots
  子树里；
- 上下文由 `InfiniteCombobox` 自动填充。只有当你不用 InfiniteCombobox、
  自己拿 `InfiniteSelect` 基座组弹层时，才需要用
  `InfiniteSelectActionsProvider` 亲自喂值：

```tsx
<InfiniteSelectActionsProvider value={{ selectedItems, selectedIds, clear, close }}>
  <InfiniteSelect {/* … */}>{slots}</InfiniteSelect>
</InfiniteSelectActionsProvider>
```

上下文定义在基座层而不是 combobox 层，是为了避免循环导入：combobox 已经
导入基座，钩子若住在上层，基座再反向导入就成环了——业务层做同类分层时同理。

## 数据适配器

组件不做请求。`list` prop 接受任何满足 `InfiniteSelectAdapterProps<T>` 的对象：

```ts
interface InfiniteSelectAdapterProps<T> {
  items: T[]
  isLoading: boolean
  isFetchingNextPage: boolean
  hasNextPage: boolean
  isError: boolean
  onLoadMore: () => void
  onRetry: () => void
}
```

用 react-query 时它就是 `useInfiniteQuery` 的一层薄壳：

```ts
function usePersonList(query: string | undefined): InfiniteSelectAdapterProps<Person> {
  const q = useInfiniteQuery({
    queryKey: ['people', query],
    queryFn: ({ pageParam }) => fetchPeople({ cursor: pageParam, query }),
    initialPageParam: undefined as string | undefined,
    getNextPageParam: (last) => last.nextCursor,
  })
  return {
    items: q.data?.pages.flatMap((p) => p.items) ?? [],
    isLoading: q.isLoading,
    isFetchingNextPage: q.isFetchingNextPage,
    hasNextPage: q.hasNextPage,
    isError: q.isError,
    onLoadMore: () => void q.fetchNextPage(),
    onRetry: () => void q.refetch(),
  }
}
```

搜索的分工：`inputValue` 是输入框的即时值（React Aria ComboBox 的同名概念），
`queryValue` 是防抖 300ms 后的请求值（可用 `debounceMs` 调）。把
`state.queryValue` 传给适配器即可；关闭弹层后再次打开会自动清空搜索。

## 自定义行内容

`renderItem` 替换的是行**内容**，不是行本身 —— `ListBoxItem` 外壳保留，
键盘导航和选中语义不受影响。签名：

```ts
renderItem?: (params: InfiniteSelectItemRenderParams<T>) => ReactNode

interface InfiniteSelectItemRenderParams<T> {
  /** 这一行对应的原始数据对象。 */
  item: T
  /** getOption(item) 的结果:id / label / textValue / isDisabled。 */
  option: InfiniteSelectOption
  /** 行在当前已加载列表中的位置,从 0 开始。语义见下方说明。 */
  index: number
  // React Aria 的 render-prop 状态词汇,整包透传 —— 与「选项行」状态表逐行对应
  isSelected: boolean
  isHovered: boolean
  isPressed: boolean
  isFocused: boolean
  isFocusVisible: boolean
  isDisabled: boolean
  /** 面板的选择模式(用于决定要不要自绘勾选框)。 */
  selectionMode: 'single' | 'multiple'
  /** React Aria 的选择行为。 */
  selectionBehavior: 'toggle' | 'replace'
}
```

提供 `renderItem` 后默认行内容整体不再渲染——包括多选的勾选框和单选的对勾，
需要这些视觉时用 `isSelected` / `selectionMode` 自行绘制：

<ComponentPreview name="infinite-select/render-item" />

```tsx
<InfiniteCombobox<Person>
  renderItem={({ item, index, isSelected }) => (
    <>
      <span className="w-8 text-right text-xs tabular-nums text-muted-foreground">
        {index + 1}.
      </span>
      <span className="flex-1 truncate">{item.name}</span>
      <span className="text-xs text-muted-foreground">{item.role}</span>
      {isSelected && <span className="text-xs text-primary">✓</span>}
    </>
  )}
  {/* … */}
/>
```

`index` 是这一行在**当前已加载列表**里的位置，从 0 开始，用来做序号、斑马纹这类
「第几行」的展示。两点注意：

- 它不是稳定标识。搜索或翻页之后，同一条数据的 `index` 会变——要唯一标识一行，
  用 `option.id`。
- 开了 `virtualized` 就别再用 CSS 的 `nth-child` 做奇偶条纹。那时 DOM 里只有
  滚动位置附近的几十行，`nth-child` 数的是这几十行的相对位置，一滚动奇偶就错乱；
  `index` 数的是完整列表的位置，不受滚动影响。

`label` 不是纯字符串时，请在 `getOption` 里补 `textValue`，typeahead 靠它检索。

## 组合式架构与 hooks

严格对齐 React Aria 的三层结构：

1. **Hooks 层**（`useXxxState` 语义）——
   `useInfiniteSelectSelection` 管选择：受控/非受控 ids、跨页对象缓存、
   RAC `Selection` → 业务 `onChange` 的翻译；`useInfiniteComboboxState`
   管弹层开合与搜索/防抖；`useDataPaginationState` 是同一模式在分页器上的应用。
   全部导出，可脱离组件 headless 使用。
2. **Parts 层（组合式组件 + context 接线）**——根组件 `InfiniteSelect` 只提供
   数据与选择的 context 和 RAC `Autocomplete` 外壳；`InfiniteSelectSearch`
   （搜索框）、`InfiniteSelectList`（列表，含虚拟化与预取）、状态插槽、footer
   一族都是普通 children，**按书写顺序渲染**，各自带自己的 props：

   ```tsx
   <InfiniteSelect
     {...list}
     getOption={getOption}
     selectionMode="multiple"
     value={ids}
     onChange={(items, nextIds) => setIds(nextIds)}
     inputValue={state.inputValue}
     onInputChange={state.setInputValue}
   >
     <InfiniteSelectSearch placeholder="搜索…" />
     <InfiniteSelectList virtualized />
     <InfiniteSelectEmpty>没有结果</InfiniteSelectEmpty>
   </InfiniteSelect>
   ```

   搜索框与列表之间不用手动接线——根组件的 `Autocomplete` 会通过 RAC 自己的
   context 把任意深度的 `SearchField` / `ListBox` 后代配对（虚拟焦点、过滤）。
   自定义 part 用 `useInfiniteSelectContext()` 读根组件提供的接线
   （items / getOption / selectionMode / selectedIds / onSelectionChange …）。
3. **便利层** —— `InfiniteCombobox` 用一组扁平 props 把弹层 + parts + 插槽
   组好，是业务代码的默认入口；它内部就是上面那段组合代码。

## 导出的类型

除组件外，`@gedatou/cadenza-ui` 还导出以下类型，供业务层封装和数据适配器使用：

| 类型 | 说明 |
| --- | --- |
| `InfiniteSelectOption` | `getOption` 的返回形状：`{ id, label, textValue?, isDisabled? }` |
| `InfiniteSelectItemRenderParams<T>` | `renderItem` 的参数，见上节 |
| `InfiniteSelectAdapterProps<T>` | `list` prop 的契约——数据适配器要实现的形状，见「数据适配器」 |
| `ControllableSelectionProps<T>` | 选择相关 props 的判别联合，判别键是 `selectionMode`（单选 `value?: string` / 多选 `value?: string[]`，`onChange` 签名随之切换） |
| `InfiniteSelectProps<T>` / `InfiniteComboboxProps<T>` | 根组件与便利层的完整 props，业务层包一层时直接复用 |
| `InfiniteSelectSearchProps` / `InfiniteSelectListProps<T>` | 两个 parts 的 props |
| `InfiniteSelectContextValue<T>` | `useInfiniteSelectContext()` 的返回——自定义 part 可读的接线 |
| `InfiniteSelectSelectionState<T>` | `useInfiniteSelectSelection()` 的返回：`selectedIds` / `selectedItems` / `onSelectionChange` |
| `InfiniteSelectActions<T>` | 动作上下文的值形状（`useInfiniteSelectActions()` 的返回 / `InfiniteSelectActionsProvider` 的入参），见「动作上下文」 |
| `InfiniteComboboxState<T>` / `InfiniteComboboxStateOptions` | `useInfiniteComboboxState` 的返回值与入参 |
| `InfiniteComboboxChildren<T>` | trigger 的类型：`ReactElement` 或接收状态的函数 |

## Props

顺序规则：**必填 → 非受控默认值 → 受控值 → 回调 → 行为开关 → 外观 → 类名**。

每个部件的 Props 表后面跟一张**状态**表。左列是挂在 DOM 上的 `data-*`，Tailwind 直接
当变体写（`data-selected:bg-accent`）；右列是同一个状态在 render props / `renderItem`
参数里的名字。`data-rac` / `data-collection` / `data-key` 是 React Aria 的内部标记，
不要依赖。

### InfiniteCombobox

便利层：一个 props 面，内部拆开路由到根组件和各个 part。改用组合式写法时，
`searchPlaceholder` 去 `InfiniteSelectSearch` 上找 `placeholder`，
`renderItem` / `virtualized` / `rowHeight` / `maxListHeight` / `scrollbars` /
`loadingMoreIndicator` / `loadMoreScrollOffset` 都在 `InfiniteSelectList` 上。

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `state` | `InfiniteComboboxState` | — | **必填**，来自 `useInfiniteComboboxState()` |
| `list` | `InfiniteSelectAdapterProps<T>` | — | **必填**，数据适配器 |
| `getOption` | `(item: T) => InfiniteSelectOption` | — | **必填**，提取 id / label / textValue / isDisabled |
| `children` | `ReactElement` \| `(state) => ReactElement` | — | **必填**。触发器，必须是可按压元素（RAC pressable）；函数形式可拿到 `isOpen` / `selectedItems` / `selectedValue` / `isDisabled` |
| `selectionMode` | `'single' \| 'multiple'` | `'single'` | 判别式：决定下面三个的类型（React Aria 的枚举，与 DataTable 同名） |
| `defaultValue` | `string` \| `string[]` | — | 非受控初始选择 |
| `value` | `string` \| `string[]` | — | 受控选择 |
| `onChange` | 单选 `(item?: T) => void`；多选 `(items: T[], ids: string[]) => void` | — | 多选时 `ids` 才是权威值，`items` 只含已加载页的对象 |
| `isDisabled` | `boolean` | `false` | 禁用整个选择器：触发器元素会被注入 `isDisabled`（RAC pressable 契约），弹层不可打开 |
| `commitOnClose` | `boolean` | `false` | 多选草稿模式，关弹层才提交 |
| `closeOnSelect` | `boolean` | `true` | 单选选中后自动关闭 |
| `lockScroll` | `boolean` | `false` | 锁定页面滚动（模态感） |
| `closeOnScroll` | `boolean` | `false` | 页面滚动时关闭弹层（原生 select 感）；默认弹层随锚点滚动、保持打开 |
| `searchPlaceholder` | `string` | — | 搜索框占位符，同时兼作它的无障碍名 |
| `renderItem` | `(params: InfiniteSelectItemRenderParams<T>) => ReactNode` | — | 替换行内容（`ListBoxItem` 外壳保留），参数见「自定义行内容」 |
| `loadingMoreIndicator` | `ReactNode` | — | 列表末尾的加载更多指示（滚动流内） |
| `loadMoreScrollOffset` | `number` | `1` | 预取距离：提前多少个视口高度触发 `onLoadMore` |
| `virtualized` | `boolean` | `false` | TanStack Virtual 行虚拟化，大数据集用 |
| `rowHeight` | `number` | `32` | 虚拟化行的固定高度；自定义 `renderItem` 更高时需同步调整 |
| `maxListHeight` | `number` | `256` | 列表最大高度 |
| `scrollbars` | `'always' \| 'hover' \| 'hidden'` | `'hover'` | 滚动条可见性：常显 / hover 与滚动时显示 / 常隐 |
| `slots` | `ReactNode` | — | 状态插槽 + footer |
| `aria-label` | `string` | 取 `searchPlaceholder` | 面板的无障碍名 |
| `selectClassName` | `string` | — | 弹层内根组件的类名 |
| `contentClassName` | `string` | — | 弹层本身的类名 |
| `popoverProps` | `Omit<PopoverProps, 接线项>` | — | 弹层定位面：`placement` / `offset` / `shouldFlip`…… 接线项（`trigger` / `isNonModal` / 开合三件套 / `className`）已从类型里排除，接线写在展开之后、始终占上风 |

防抖不在这张表上 —— `debounceMs`（默认 `300`）是 `useInfiniteComboboxState()` 的选项。

**状态**（弹层，`data-slot="infinite-combobox-content"`）

| 状态 | 出现时机 | 说明 |
| --- | --- | --- |
| `data-placement` | 弹层已定位，值是 `bottom` / `top` / … | 出场动画按方向分岔时挂这个 |
| `data-trigger` | 默认是 `SubmenuTrigger`（借该分支换取「弹层随锚点滚动」，不是真的子菜单）；`lockScroll` / `closeOnScroll` 下回落为 `DialogTrigger` | 出场动画等选择器谨慎依赖此值 |

触发器是你自己传的 `children`，状态取决于你用什么渲染。用我们的 `Button` 的话，
它带 `data-hovered` / `data-pressed` / `data-focus-visible` / `data-disabled`。

### InfiniteSelect

根组件：持有数据与选择，通过 context 接线给各个 part。它自己不渲染任何文案和 part。

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `items` | `T[]` | — | **必填**，当前已加载（服务端过滤后）的数据 |
| `getOption` | `(item: T) => InfiniteSelectOption` | — | **必填**，提取 id / label / textValue / isDisabled |
| `selectionMode` | `'single' \| 'multiple'` | `'single'` | 判别式，同上 |
| `defaultValue` | `string` \| `string[]` | — | 非受控初始选择 |
| `value` | `string` \| `string[]` | — | 受控选择 |
| `onChange` | 同 `InfiniteCombobox` | — | 选择变化回调 |
| `inputValue` | `string` | — | 受控搜索词（RAC ComboBox 的词汇） |
| `onInputChange` | `(value: string) => void` | — | 搜索词变化回调 |
| `isLoading` | `boolean` | `false` | 首屏加载中 |
| `isFetchingNextPage` | `boolean` | `false` | 正在取下一页 |
| `hasNextPage` | `boolean` | `false` | 还有下一页 |
| `isError` | `boolean` | `false` | 加载失败 |
| `onLoadMore` | `() => void` | — | 触底（或提前一个视口）时调用 |
| `onRetry` | `() => void` | — | 给 `InfiniteSelectRetry` 用；不传则该插槽不渲染 |
| `aria-label` | `string` | — | 面板无障碍名，`InfiniteSelectList` 会回退到它 |
| `children` | `ReactNode` | — | part / 状态插槽 / footer，按调用方书写顺序渲染 |
| `className` | `string` | — | 根元素类名 |

**状态** —— 根元素上没有状态属性，它只是 RAC `Autocomplete` 的容器。状态都在下面的
part 上。

### InfiniteSelectSearch

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `placeholder` | `string` | — | 默认组合里输入框的占位符，同时兼作无障碍名。**没有默认文案**——基座零可见文案；两者都没传时无障碍名兜底为 `'Search'`（只进 aria，不上屏） |
| `autoFocus` | `boolean` | `false` | 挂载即聚焦。默认关闭（内联面板不该抢页面焦点）；`InfiniteCombobox` 会传 `true`，弹层一开就能打字 |
| `children` | `ReactNode` | 图标 + 输入框 | 传了就完全接管内部结构；里面的 RAC `Input` 由字段 context 自动接线，`placeholder` / `autoFocus` 只作用于默认组合 |
| `className` | `string \| (state) => string` | — | 类名，函数形式收到下表的 render props |
| 其余 | RAC `SearchField` 的 props | — | 透传（`onSubmit`、`isDisabled`、`isReadOnly`……）。**除** `value` / `defaultValue` / `onChange` —— 那是根组件 `Autocomplete` 的过滤接线，已保留不放开 |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-empty` | 搜索框没有内容（RAC `SearchField`，清除按钮靠它显隐） | `isEmpty` |
| `data-disabled` | 透传 `isDisabled` 时 | `isDisabled` |

### InfiniteSelectList

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `aria-label` | `string` | 回退到根组件的 | 列表的无障碍名 |
| `renderItem` | `(params: InfiniteSelectItemRenderParams<T>) => ReactNode` | — | 替换行内容，`ListBoxItem` 外壳保留 |
| `loadingMoreIndicator` | `ReactNode` | — | 滚动流内的加载更多指示 |
| `loadMoreScrollOffset` | `number` | `1` | 预取距离，单位是视口高度 |
| `virtualized` | `boolean` | `false` | 行虚拟化 |
| `rowHeight` | `number` | `32` | 虚拟化行的固定高度 |
| `maxListHeight` | `number` | `256` | 最大高度 |
| `scrollbars` | `'always' \| 'hover' \| 'hidden'` | `'hover'` | 滚动条可见性 |
| `className` | `string` | — | 外层滚动容器的类名（尺寸约束定在这里） |
| `listClassName` | `string \| (state) => string` | — | RAC `ListBox` 本体的类名，函数形式收到它的 render props |
| `itemClassName` | `string \| (state) => string` | — | 每一行的类名，函数形式收到该行的 render props（见「选项行」状态表） |

**状态**

| 状态 | 出现时机 | render prop |
| --- | --- | --- |
| `data-layout` | 固定是 `stack`（RAC `ListBox` 的布局模式） | `layout` |
| `data-orientation` | 固定是 `vertical` | `orientation` |

### 选项行

不是一个可写的组件 —— 由 `InfiniteSelectList` 渲染的 RAC `ListBoxItem`，
`data-slot="infinite-select-item"`。`renderItem` 换掉的是它的**内容**，外壳、
键盘导航和选择接线都还在，所以下面这些状态照常可用。

**状态**

| 状态 | 出现时机 | renderItem 参数 |
| --- | --- | --- |
| `data-selection-mode` | 始终有值：`single` / `multiple` | `selectionMode` |
| `data-selected` | 该项已选中 | `isSelected` |
| `data-hovered` | 指针悬停其上；触摸和键盘都不触发 | `isHovered` |
| `data-pressed` | 指针按住未松开 | `isPressed` |
| `data-focused` | 是当前的活动项（虚拟焦点，真实焦点留在搜索框） | `isFocused` |
| `data-focus-visible` | 活动项**且**由键盘导航到达 | `isFocusVisible` |
| `data-disabled` | `getOption` 返回了 `isDisabled: true` | `isDisabled` |

`renderItem` 的参数是 `item` / `option` / `index` 加上表里的全套 RAC 状态词汇
（另有 `selectionBehavior`）。参数带全不增加渲染成本 —— 行为了更新 `data-*`
属性本来就会在这些状态变化时重渲染；样式仍然优先走 CSS 变体，参数是给
需要按状态换内容（不只换样式）的渲染器用的。

搜索框保持真实焦点、列表项拿虚拟焦点，是 RAC `Autocomplete` 的设计：这样打字和
上下键可以同时工作。所以焦点样式要挂在 `data-focused` 上，别挂 `:focus`。

### 状态插槽与 footer

这几个部件都没有自己的 props（除了 `className` 和原生属性透传），文案由 `children`
决定，是否渲染由 context 里的状态决定 —— 详见[插槽](#插槽)与[动作上下文](#动作上下文)。

| 部件 | 何时渲染 | data-slot |
| --- | --- | --- |
| `InfiniteSelectEmpty` | 加载完、无错误、`items` 为空 | `infinite-select-status` |
| `InfiniteSelectError` | `isError` | `infinite-select-status` |
| `InfiniteSelectRetry` | 在 `Error` 内，且根上传了 `onRetry` | `infinite-select-retry` |
| `InfiniteSelectFooter` | 总是（由调用方决定放不放） | `infinite-select-footer` |
| `InfiniteSelectFooterSeparator` | 总是 | `infinite-select-footer-separator` |
| `InfiniteSelectLoadingOverlay` | 标记部件：原地不渲染，props 被提升到列表壳的覆盖层上 | 提升后为 `loading-overlay` |
| `InfiniteSelectClearButton` | 总是 | `infinite-select-clear` |
| `InfiniteSelectConfirmButton` | 总是 | `infinite-select-confirm` |

三个状态插槽共用一个 `role="status"` 的容器，所以变化会被读屏播报一次，而不是三种
写法各播一次。
