import { SingleDemo, MultiDemo, ErrorDemo, VirtualizedDemo, RenderItemDemo } from '../../../components/InfiniteSelectDemo'

可搜索、游标分页无限滚动的选择器家族。行为全部由 React Aria 承担：`Autocomplete`
用虚拟焦点把搜索框和列表接起来（输入框保持 DOM 焦点，方向键在列表里移动），
`ListBox` 提供选择语义、方向键 / Home / End / typeahead。大数据集可用
`virtualized` 开启 TanStack Virtual 行虚拟化，见下文。

下面的 demo 用 Promise 模拟异步接口（300–500ms 随机延时）。

## 单选

打开后滚到底会自动加载下一页；输入会防抖 300ms 后落到 `queryValue`，由数据层重新请求。

<SingleDemo client:load />

```tsx
import {
  Button,
  InfiniteCombobox,
  useInfiniteComboboxState,
} from '@gedatou/cadenza-ui'

function PersonPicker() {
  const state = useInfiniteComboboxState()
  const list = usePersonList(state.queryValue) // 你的数据适配器,见下文
  const [picked, setPicked] = useState<Person>()

  return (
    <InfiniteCombobox<Person>
      getOption={(p) => ({ id: p.id, label: p.name })}
      list={list}
      onChange={setPicked}
      searchPlaceholder="搜索作曲家…"
      slots={slots}
      state={state}
    >
      <Button variant="outline">{picked?.name ?? '选择作曲家'}</Button>
    </InfiniteCombobox>
  )
}
```

触发器是 `children`，必须是 React Aria 意义上可按压的元素（库里的 `Button` 即可）——
弹层开合、焦点归还、Esc 关闭都由 `DialogTrigger` 接管。传函数可以拿到当前状态做摘要展示。

## 多选 + 暂存提交

`commitOnClose` 下，弹层内的勾选只是草稿，**关闭弹层才提交一次** `onChange` ——
适合筛选场景（每勾一下就请求一次太吵）。footer 里的清空 / 确定通过 context 拿到
`clear` / `close`，不需要你穿线。

<MultiDemo client:load />

```tsx
<InfiniteCombobox<Person>
  commitOnClose
  multiple
  value={ids}
  onChange={(items, nextIds) => setIds(nextIds)}
  slots={(
    <>
      {slots}
      <InfiniteSelectFooter>
        <InfiniteSelectClearButton>清空</InfiniteSelectClearButton>
        <InfiniteSelectConfirmButton>确定</InfiniteSelectConfirmButton>
      </InfiniteSelectFooter>
    </>
  )}
  {/* … */}
>
  <Button variant="outline">已选 {ids.length} 位</Button>
</InfiniteCombobox>
```

多选的 `onChange(items, ids)` 里 **`ids` 是权威全集**：预选 id 落在未加载的页上时，
它有 id 没对象，`items` 只回显已加载的那些。持久化请存 `ids`。

## 虚拟化

默认情况下，加载了多少行就渲染多少行。开启 `virtualized` 后行渲染交给
TanStack Virtual：**任何时刻只有视口内可见的行、加上视口外少量预渲染的行
（overscan）存在于 DOM**——加载一万行，DOM 里也始终只有几十个节点。
下面的 demo 一次拉满 10000 条（无翻页）：

<VirtualizedDemo client:load />

```tsx
<InfiniteCombobox<Person> virtualized rowHeight={32} … />
```

开启前要知道的三个取舍：

1. **行高固定**为 `rowHeight`（默认 32px）——虚拟化靠固定行高换取零测量、零跳动；
   自定义 `renderItem` 比默认行高时必须同步调大它。
2. **键盘和读屏的作用域变窄**：React Aria 只认识 DOM 里的那几十行，所以打字定位
   （typeahead）、Home / End 只在这几十行内生效，读屏播报的列表总数也是这个数。
3. 因此**几百行以内不建议开**——不开时 React Aria 认识完整列表，上面这些能力
   都是全量的，而几百行的 DOM 根本不构成性能问题。

加载下一页的触发时机与非虚拟模式一致（提前约 1.5 个视口预取），无需关心。

## 状态插槽

基座**零文案**。空 / 加载 / 错误 / 加载更多都是 context 驱动的插槽组件，按状态自渲染、
互斥，文案由你注入 —— i18n 只存在于你的业务层：

<ErrorDemo client:load />

```tsx
const slots = (
  <>
    <InfiniteSelectLoading>加载中…</InfiniteSelectLoading>
    <InfiniteSelectEmpty>没有匹配的结果</InfiniteSelectEmpty>
    <InfiniteSelectError>
      加载失败
      <InfiniteSelectRetry>重试</InfiniteSelectRetry>
    </InfiniteSelectError>
  </>
)
```

加载更多的指示不走插槽——它必须渲染在**列表滚动流的末尾**（位置由基座决定），
用 `loadingMoreIndicator` prop 传：预取提前一个视口触发，停在顶部的用户根本看不到它，
只有滚到底部、恰好在等下一页的人才会看见。

`InfiniteSelectRetry` 自己接好基座的 `onRetry`（没有则不渲染），你只出文案。
所有状态共用一个 `role="status"` 容器，状态切换会被读屏播报。

## 数据适配器

组件不做请求。`list` prop 接受任何满足 `InfiniteSelectAdapterProps<T>` 的对象：

```ts
interface InfiniteSelectAdapterProps<T> {
  items: T[]
  isLoading: boolean
  isFetchingNextPage: boolean
  hasNextPage: boolean
  isError: boolean
  onLoadMore: () => void
  onRetry: () => void
}
```

用 react-query 时它就是 `useInfiniteQuery` 的一层薄壳：

```ts
function usePersonList(query: string | undefined): InfiniteSelectAdapterProps<Person> {
  const q = useInfiniteQuery({
    queryKey: ['people', query],
    queryFn: ({ pageParam }) => fetchPeople({ cursor: pageParam, query }),
    initialPageParam: undefined as string | undefined,
    getNextPageParam: (last) => last.nextCursor,
  })
  return {
    items: q.data?.pages.flatMap((p) => p.items) ?? [],
    isLoading: q.isLoading,
    isFetchingNextPage: q.isFetchingNextPage,
    hasNextPage: q.hasNextPage,
    isError: q.isError,
    onLoadMore: () => void q.fetchNextPage(),
    onRetry: () => void q.refetch(),
  }
}
```

搜索的分工：`searchValue` 是输入框的即时值，`queryValue` 是防抖 300ms 后的请求值
（可用 `debounceMs` 调）。把 `state.queryValue` 传给适配器即可；关闭弹层后再次打开会自动清空搜索。

## 自定义行内容

`renderItem` 替换的是行**内容**，不是行本身 —— `ListBoxItem` 外壳保留，
键盘导航和选中语义不受影响。签名：

```ts
renderItem?: (params: InfiniteSelectItemRenderParams<T>) => ReactNode

interface InfiniteSelectItemRenderParams<T> {
  /** 这一行对应的原始数据对象。 */
  item: T
  /** getOption(item) 的结果:id / label / textValue / disabled。 */
  option: InfiniteSelectOption
  /** 行在当前已加载列表中的位置,从 0 开始。语义见下方说明。 */
  index: number
  /** 该行当前是否选中。 */
  selected: boolean
  /** 面板是否处于多选模式(用于决定要不要自绘勾选框)。 */
  isMultiple: boolean
}
```

提供 `renderItem` 后默认行内容整体不再渲染——包括多选的勾选框和单选的对勾，
需要这些视觉时用 `selected` / `isMultiple` 自行绘制：

<RenderItemDemo client:load />

```tsx
<InfiniteCombobox<Person>
  renderItem={({ item, index, selected }) => (
    <>
      <span className="w-8 text-right text-xs tabular-nums text-muted-foreground">
        {index + 1}.
      </span>
      <span className="flex-1 truncate">{item.name}</span>
      <span className="text-xs text-muted-foreground">{item.role}</span>
      {selected && <span className="text-xs text-primary">✓</span>}
    </>
  )}
  {/* … */}
/>
```

`index` 是这一行在**当前已加载列表**里的位置，从 0 开始，用来做序号、斑马纹这类
「第几行」的展示。两点注意：

- 它不是稳定标识。搜索或翻页之后，同一条数据的 `index` 会变——要唯一标识一行，
  用 `option.id`。
- 开了 `virtualized` 就别再用 CSS 的 `nth-child` 做奇偶条纹。那时 DOM 里只有
  滚动位置附近的几十行，`nth-child` 数的是这几十行的相对位置，一滚动奇偶就错乱；
  `index` 数的是完整列表的位置，不受滚动影响。

`label` 不是纯字符串时，请在 `getOption` 里补 `textValue`，typeahead 靠它检索。

## 导出的类型

除组件外，`@gedatou/cadenza-ui` 还导出以下类型，供业务层封装和数据适配器使用：

| 类型 | 说明 |
| --- | --- |
| `InfiniteSelectOption` | `getOption` 的返回形状：`{ id, label, textValue?, disabled? }` |
| `InfiniteSelectItemRenderParams<T>` | `renderItem` 的参数，见上节 |
| `InfiniteSelectAdapterProps<T>` | `list` prop 的契约——数据适配器要实现的形状，见「数据适配器」 |
| `ControllableSelectionProps<T>` | 选择相关 props 的判别联合（单选 `value?: string` / 多选 `value?: string[]`，`onChange` 签名随之切换） |
| `InfiniteSelectProps<T>` / `InfiniteComboboxProps<T>` | 两个组件的完整 props，业务层包一层时直接复用 |
| `InfiniteSelectActions<T>` | footer 内 `useInfiniteSelectActions()` 的返回：`selectedItems` / `selectedIds` / `clear` / `close` |
| `InfiniteComboboxState<T>` / `InfiniteComboboxStateOptions` | `useInfiniteComboboxState` 的返回值与入参 |
| `InfiniteComboboxChildren<T>` | trigger 的类型：`ReactElement` 或接收状态的函数 |

## 键盘交互

| 按键 | 行为 |
| --- | --- |
| `↓` / `↑` | 在列表中移动（输入框保持焦点） |
| `Enter` | 选中当前项 |
| `Esc` | 先清空搜索词，再次按下关闭弹层 |
| 打字 | 过滤（经防抖交给数据层） |

## Props

`InfiniteCombobox` 除下表外的 props 透传规则见类型定义。

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `state` | `InfiniteComboboxState` | — | 来自 `useInfiniteComboboxState()` |
| `list` | `InfiniteSelectAdapterProps<T>` | — | 数据适配器 |
| `getOption` | `(item: T) => InfiniteSelectOption` | — | 提取 id / label / textValue / disabled |
| `multiple` | `boolean` | `false` | 多选模式 |
| `value` / `defaultValue` | `string` \| `string[]` | — | 受控 / 非受控选择 |
| `commitOnClose` | `boolean` | `false` | 多选草稿模式，关弹层才提交 |
| `closeOnSelect` | `boolean` | `true` | 单选选中后自动关闭 |
| `lockScroll` | `boolean` | `false` | 锁定页面滚动（模态感） |
| `closeOnScroll` | `boolean` | `false` | 页面滚动时关闭弹层（原生 select 感）；默认弹层随锚点滚动、保持打开 |
| `slots` | `ReactNode` | — | 状态插槽 + footer |
| `loadingMoreIndicator` | `ReactNode` | — | 列表末尾的加载更多指示（滚动流内） |
| `loadMoreScrollOffset` | `number` | `1` | 预取距离：提前多少个视口高度触发 `onLoadMore` |
| `renderItem` | `(params: InfiniteSelectItemRenderParams<T>) => ReactNode` | — | 替换行内容（`ListBoxItem` 外壳保留），参数见「自定义行内容」 |
| `maxListHeight` | `number` | `256` | 列表最大高度 |
| `scrollbars` | `'always' \| 'hover' \| 'hidden'` | `'hover'` | 滚动条可见性：常显 / hover 与滚动时显示 / 常隐 |
| `virtualized` | `boolean` | `false` | TanStack Virtual 行虚拟化，大数据集用 |
| `rowHeight` | `number` | `32` | 虚拟化行的固定高度；自定义 `renderItem` 更高时需同步调整 |
| `debounceMs`（state 上） | `number` | `300` | 搜索 → 请求的防抖 |
